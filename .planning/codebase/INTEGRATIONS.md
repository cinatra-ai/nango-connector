# External Integrations

**Analysis Date:** 2026-06-09

## APIs & External Services

**Credential Vault / OAuth Proxy:**
- Nango — central integration hub; manages OAuth flows, token storage, and automatic refresh for all connectors
  - SDK/Client (server): `@nangohq/node` — used in `src/nango.ts`
  - SDK/Client (browser): `@nangohq/frontend` — used in `src/nango-connect-ui.ts`
  - Auth: `NANGO_SECRET_KEY` env var (server); public session token issued per-OAuth-flow (browser)
  - Default API endpoint: `https://api.nango.dev`
  - Connect UI endpoint: `https://connect.nango.dev` (derived from server URL or `NANGO_PUBLIC_CONNECT_URL`)
  - Admin HTTP calls: `GET/PUT /api/v1/connect-ui-administration` (watermark suppression in `src/nango.ts`)

**Connected Third-Party Services (via Nango):**
All connections below are brokered through Nango; this package stores only the Nango connection record, not raw credentials.

- **Anthropic (Claude API)** — `cinatra-anthropic` provider config key; API-key credential
- **OpenAI API** — `cinatra-openai`; API-key credential
- **Google Gemini API** — `cinatra-google-gemini`; API-key credential
- **Gmail** — `cinatra-gmail`; OAuth2
- **Google Calendar** — `cinatra-google-calendar`; OAuth2
- **Google OAuth (app-level)** — `cinatra-google-oauth`; stores OAuth2 client_id + client_secret for Gmail/Calendar/Sign-in; credentials read in `src/nango.ts:getNangoGoogleOAuthClientCredentials()`
- **GitHub** — `cinatra-github`; OAuth2
- **LinkedIn** — `cinatra-linkedin`; OAuth2; `multiple: true` (multi-account)
- **Apollo** — `cinatra-apollo`; API-key credential
- **Apify** — `cinatra-apify`; API-key credential; single workspace token
- **WordPress** — `cinatra-wordpress`; per-site Bearer token; `multiple: true`
- **Drupal** — `cinatra-drupal`; per-site Bearer token generated by `drush mcp-tools:remote-key-create`; `multiple: true`
- **YouTube** — `cinatra-youtube`; OAuth2
- **Tailscale** — `cinatra-tailscale`; OAuth2 client credentials (client_id + client_secret) stored at integration level; per-clone auth-keys minted via Tailscale API at runtime (not stored in Nango)
- **A2A Server** — `cinatra-a2a-server`; generic agent-to-agent peer; API-key/bearer; `multiple: true`

All provider config keys defined in `src/nango.ts:CINATRA_NANGO_PROVIDER_CONFIG_KEYS`.
All connector definitions (title, description, `usesConnectUI`, `multiple`) in `src/nango-connectors.ts:NANGO_CONNECTOR_DEFINITIONS`.

## Data Storage

**Databases:**
- PostgreSQL (via host app) — connector configuration and connection records are persisted through `@/lib/database` functions:
  - `readConnectorConfigFromDatabase` — reads settings/connection store
  - `writeConnectorConfigToDatabase` — writes settings/connection store
  - `deleteConnectorConfig` — deletes a connector config key (used for legacy key purge)
- Connector IDs used as DB keys: `"nango"` (settings), `"nango_connections"` (connection store)
- This package does NOT manage the DB schema directly; the host app owns it

**File Storage:**
- Not applicable

**Caching:**
- None — every read calls the DB directly; a cold-boot fallback returns empty settings on Postgres timeout

## Authentication & Identity

**Auth Provider:**
- Nango — OAuth flows are initiated via `createNangoConnectSession` (`src/nango-connect-ui.ts`) which mints a short-lived session token
- User-scoped connections include Nango end-user identity (`src/nango.ts:buildNangoUserEndUserId` → `cinatra-user:{userId}`)
- App-scoped connections use workspace-level credentials with no end-user association

**Webhook Auth:**
- Nango webhook signature verification is the responsibility of the host route that calls `handleNangoWebhook` (`src/route-handlers.ts`)

## Environment Configuration

**Required env vars:**
- `NANGO_SECRET_KEY` — Nango server-side bearer token (required for any Nango operation)

**Optional env vars:**
- `NANGO_SERVER_URL` — self-hosted Nango server base URL (defaults to `https://api.nango.dev`)
- `NANGO_PUBLIC_CONNECT_URL` — override for Nango Connect UI base URL (derived from `NANGO_SERVER_URL` if omitted)

**Secrets location:**
- No `.env` file in this repo; env vars are injected by the host application at runtime

## Webhooks & Callbacks

**Incoming:**
- Nango auth webhook — `handleNangoWebhook` in `src/route-handlers.ts` processes `NangoAuthWebhookBody` events (connection created/deleted) sent by Nango after OAuth completion; the host app must mount this handler at its own route

**Outgoing:**
- OAuth redirect — Nango's hosted Connect UI redirects back to the Nango-hosted callback URL; no custom outbound webhooks
